For roughly a decade, application-prep sites repeated the same warning: PDFs confuse applicant
tracking systems, so submit a Word file to be safe. Then the software companies started publishing
guidance of their own — and Greenhouse's candidate FAQ now says, in four words, "Upload a **PDF**
for best results." **When the advice and the vendor's documentation disagree, the documentation
wins — it describes the actual parser your file will meet.**

## The failure

The mistake this page prevents is spending your worry on the file extension while ignoring what the
vendors actually flag: the layout inside the file. Candidates export a careful, clean CV to .docx
out of format superstition — or, worse, assume format anxiety was the whole story and pour effort
into a two-column design with icons and a name banner, which is precisely what the parsing
documentation warns about. The extension was never the main risk. The decoration is.

## What the vendors say about formats

> "Upload a **PDF** for best results."
> — Greenhouse, MyGreenhouse FAQ for Candidates

> "Some applicant tracking systems did not parse resumes well outside of Microsoft Word documents
> ... Today, most ATS vendors have fixed these tricks and read PDFs and other file types
> accurately."
> — iCIMS, applicant tracking system glossary

> "Resume parsing results can vary based on resume format and order of words. For best results, use
> resumes that don't have images or image-based styles."
> — Workday, "Concept: Resume Parsing"

iCIMS elsewhere describes parsing as software that "extracts data, usually from a Word or PDF
document, and converts it in a structured way" — both formats named as routine inputs, neither
warned against. Oracle Taleo's configuration guide lists the file types the system supports:
Word (.doc and .docx), PDF, RTF, plain text, HTML, OpenOffice, even WordPerfect — with the note
that "System administrators define which formats are available to users", so the upload form
itself shows you what a given employer accepts.

**In the vendor documentation gathered for this site, no ATS maker advises Word over PDF.** The
"PDFs break the ATS" warning describes a historical problem — iCIMS's own word — that third-party
advice kept alive long after the parsers moved on.

## What actually breaks parsing

Greenhouse maintains a support page titled "Unsuccessful resume parse", and its list of causes is
about layout and size, not extension. Verbatim entries include:

| Greenhouse-listed cause | What it means for your CV |
| --- | --- |
| "Resumes that include graphics, photos, or word art" | Decoration is parser risk, whatever the format |
| "Resumes that have a columned layout" | Multi-column designs scramble reading order |
| "Complex resumes with tables, headers, and footers" | Keep structure in the body text |
| "Resumes with the name and contact information in the header, footer, or text box" | Contact details belong in the body, at the top |
| "Resumes that are uploaded as an image, rather than a document" | A scan or screenshot is not a document |
| "Resumes without clear sections and differing formats throughout each section" | Consistent, labelled sections |

Greenhouse also notes it "can't parse resumes larger than 2.5MB". Workday's advice points the same
way: avoid "images or image-based styles". And note what failure costs — per Greenhouse, "If a
resume fails to parse, you'll need to manually input the candidate's details into the fields."
The consequence documented by the vendor is manual data entry on the recruiter's side, not
rejection; no vendor documentation gathered for this site says a CV is auto-rejected for its
formatting.

## The habit that shrinks the whole question

Greenhouse tells candidates directly: "Resume parsing is designed to save time, but can make
mistakes. Be sure to review and edit your information before saving your profile and before
submitting all applications." Workday's documentation likewise says parsing "populates fields from
a resume, and Workday enables you to review the resume data."

**Where the application form shows you the parsed fields, checking them beats any format theory.**
If your dates, titles and employers landed in the right boxes, the format debate is over for that
application. If they didn't, fix the fields by hand — the vendors built the review step for
exactly this.

## Worked example: one header, two layouts

The same information, laid out two ways:

**Version A — clean single column, in the document body:**

```
Amira Osei
Manchester, UK · amira.osei@example.com · 07700 900123
```

**Version B — decorative:** the name sits in a page-header banner as white-on-teal word art, a
photo floats to the right, and phone and email live in a narrow left column with icons instead of
the words "phone" and "email".

Walk Version B past Greenhouse's list: name and contact in the header — listed cause. Graphics and
word art — listed cause. Columned layout — listed cause. Photo — listed cause, and a separate
issue in some countries (see the related page on photos). Every decorative choice in Version B is
individually named in the vendor's parse-failure documentation. Version A trips none of them — and
it reads faster for the human too. Saved as an ordinary PDF or .docx, it is exactly what the
parsers are built for.

## Honest limits

- **Coverage is incomplete.** Lever's help centre and SAP SuccessFactors' documentation could not
  be captured for this fact base, so this page cannot tell you what those two systems advise.
  Titles confirm both document resume parsing; the contents remain unverified here.
- **Formats are employer-configurable.** Taleo administrators choose which file types the form
  accepts — the same ATS can accept different formats at different companies.
- **A posting's instruction outranks everything on this page.** If the employer asks for a
  specific format, send that format. When in doubt, check with the target employer.

## What actually costs you

- Exporting to .docx out of PDF superstition solves a problem the vendors call historical.
- A columned, graphic-heavy layout is a documented parse risk in either format.
- Contact details in the page header or a text box — a named failure cause at Greenhouse.
- Uploading a scanned image of a CV instead of a real document.
- Skipping the review-your-parsed-fields step when the form offers it.
- Ignoring an explicit format request in the job posting.
